日志文件夹结构说明
目录结构
每次执行 apk-test run 时，自动在 log/ 下创建时间戳文件夹，结构如下：

log/
├── 20261027_153000/              ← 时间戳文件夹（YYYYMMDD_HHmmss）
│   ├── apk_test.log              ← 本次测试的运行日志
│   ├── app_v1.0.apk/             ← APK 子文件夹（以 APK 文件名命名）
│   │   ├── 45a2cacc_sdk_log.log  ← 设备 SDK 日志
│   │   └── FA7831801432_sdk_log.log
│   └── app_v2.0.apk/
│       ├── 45a2cacc_sdk_log.log
│       └── FA7831801432_sdk_log.log
各层级说明
层级	命名规则	说明
时间戳文件夹	YYYYMMDD_HHmmss	每次 apk-test run 创建一个，代表一次测试
运行日志	apk_test.log	本次测试的完整运行日志，位于时间戳文件夹根目录
APK 子文件夹	APK 文件名（含后缀）	每个被测 APK 一个文件夹，同名 APK 归入同一文件夹
SDK 日志	{device}_sdk_log.log	从设备拉取的 SDK 日志，设备序列号确保不冲突
防覆盖机制
同名 APK：同一时间戳文件夹内同名 APK 只会被测试一次，不会覆盖

不同设备：SDK 日志文件名包含设备序列号，不同设备不互相覆盖

不同轮次：每次测试创建新的时间戳文件夹，自然隔离

代码改动点
cli.py
setup_logging：日志文件名从 apk_test_{timestamp}.log 改为固定 apk_test.log

cmd_run：创建 log/{YYYYMMDD_HHmmss}/ 时间戳文件夹作为本次测试根目录

core.py
test_device：新增 apk_name 参数，内部创建 {log_dir}/{apk_name}/ 子文件夹

run_tests：新增 apk_name 参数，透传给 test_device

run_tests_batch：遍历 APK 时，为每个 APK 创建 {log_dir}/{apk_name}/ 子文件夹
