# APK 自动化测试工具 — Enable 功能改动说明

## 概述

本次改动为 APK 自动化测试工具新增了 **SDK Enable 开关设置** 功能，并修复了日志拉取逻辑中的路径回退问题。

---

## 改动一：新增 `set_sdk_enable()` 函数

### 位置

`core.py` — 新增函数

### 功能

在安装 APK 之后、启动应用之前，向设备写入 SDK enable 开关文件（`enable.log`），控制 SDK 各功能模块的开启/关闭。

### 预设 Enable 值

| 类型 | 值 | 用途 |
|------|-----|------|
| `sdk` | `0000000000000000090900009000000000000` | SDK 测试服（默认） |
| `shell` | `0000000000000000090910009000000000000` | Shell 测试服 |
| `all_1` | `1111111111111111111111111111111111111111111` | 全功能开启 |
| `official` | `0000000000000000090000009000000000000` | 正式服 |
| `perf_68` | `000000000000000009009000000000000000000000000000000000000000000000009` | 性能测试 |

### 写入逻辑

根据设备 Android API 级别选择写入路径（2026-10-28 官方口径确认的规则）：

1. **Android 10+（API ≥ 29）**：主路径为应用自身私有目录 `/sdcard/Android/data/{被测应用自身包名}/files/enable.log`
   - 注意：高版本路径中的 `{包名}` 一律指**被测应用自身包名**，不是固定的 SDK 目录
2. **Android 9-（API < 29）**：主路径为低版本路径 `/sdcard/sdk/enable.log`
3. 部分机型可能不同，因此两条路径**全部写入**（主路径优先），哪条读回验证通过算哪条
4. 写入后通过 `cat` 读回验证内容是否匹配

### 已知 SDK 接入包对照表

| APK 名称示例 | 软件名 | 包名 |
|--------------|--------|------|
| `Sdk_Tools_8.2.19_8888_c++_64.apk` | tlog_sdk | `com.tencent.sdk` |
| `ANO_Tools_8.2.19_8888_c++_64.apk` | tlog_sdk_ano | `com.tencent.sdk_ano` |
| `ACE_Tools_8.2.19_20059_c#.apk` | ACE_Tools | `com.tencent.green.ace` |
| `ANO_Tools_8.2.19_20109_c#.apk` | ANO_Tools | `com.tencent.green.ace.ano` |

> 历史纠偏：`com.tencent.green.ace` 并非"固定 SDK 目录"，它只是 ACE_Tools 演示包自己的包名。之前在 ACE_Tools 包的设备上看到日志落在 `/sdcard/Android/data/com.tencent.green.ace/files`，正是因为那就是它自己的包目录。

### 高版本路径失败时的兜底策略

- 高版本路径写入失败（如无 root 权限）时，自动回退到低版本路径 `/sdcard/sdk/enable.log`
- 低版本路径不需要 root 权限，普通用户即可写入

## 改动二：`test_device()` 函数 — 新增 `enable_set` 参数

### 位置

`core.py` — `test_device()` 函数

### 改动内容

- 新增参数 `enable_set=None`
- 在 `install_apk` 之后、`launch_app` 之前插入 `set_sdk_enable` 调用

```python
# 设置 SDK enable 开关（安装后、启动前）
if enable_set:
    set_sdk_enable(device, package_name, enable_set)
```

### 改动内容

## 改动四：CLI 命令行 — 新增 `--enable` 参数

### 位置

`cli.py` — `cmd_run()` 函数

### 改动内容

- 新增 `--enable` 命令行参数，通过 `choices` 限制输入为 5 种预设值
- 日志输出中增加 SDK Enable 信息

### 使用示例

```bash
# 设置 SDK 测试服 enable
apk-test run --apk app.apk --device 45a2cacc --enable sdk

# 全功能开启
apk-test run --apk app.apk --device 45a2cacc --enable all_1

# 正式服配置
apk-test run --apk app.apk --device 45a2cacc --enable official

# 不设置 enable（保持原行为）
apk-test run --apk app.apk --device 45a2cacc
```

### 改动五：`pull_sdk_log()` 函数 — 修复路径回退逻辑

### 位置

`core.py` — `pull_sdk_log()` 函数

### 改动内容

- 按设备 API 级别决定探测顺序：Android 10+（API ≥ 29）优先 `/sdcard/Android/data/{被测应用自身包名}/files/log.log`，Android 9-（API < 29）优先 `/sdcard/sdk/log.log`；主路径未命中时另一条路径兜底（部分机型可能不同）
- 正常只生成 `log.log`，没有 `log2.log` 伴生日志
- 设备序列号含冒号（如 `127.0.0.1:5555`）时，本地文件名会将冒号替换为下划线（Windows 合法性 + 避免 NTFS 备用数据流坑）

## 改动六：`test_device()` 函数 — 无论测试是否通过都拉取日志

### 位置

`core.py` — `test_device()` 函数

### 改动内容

在所有测试失败的分支中都加入了 `pull_sdk_log` 调用：

| 失败阶段 | 是否拉取日志 |
|---------|------------|
| 安装失败 | ✅ 是 |
| 启动失败 | ✅ 是 |
| 运行期间闪退 | ✅ 是 |
| 前后台切换异常 | ✅ 是 |
| 杀进程重启异常 | ✅ 是 |
| 全部测试通过 | ✅ 是 |

## 完整调用链路

```
CLI (--enable sdk)
  └─> run_tests(enable_set='sdk')
       └─> test_device(enable_set='sdk')
            ├─> install_apk()
            ├─> set_sdk_enable(device, pkg_name, 'sdk')  ← 新增
            │    ├─> 检查 API 级别
            │    ├─> 检查 root 权限
            │    ├─> 写入 enable.log（高版本路径优先）
            │    └─> 验证写入内容
            ├─> launch_app()
            ├─> wait_and_monitor()
            ├─> switch_background_foreground()
            ├─> kill_and_relaunch()
            ├─> pull_sdk_log()  ← 无论通过/失败都拉取
            └─> uninstall_apk()
```

## 关键注意事项

1. **模拟器无 root 权限**：普通写入失败时会自动尝试 root 方式（`su -c` / `adb root`）重试
2. **包名语义**：高版本路径中的 `{包名}` 一律指**被测应用自身包名**（工具自动从 APK 解析，或用 `--package` 指定）；`com.tencent.green.ace` 只是 ACE_Tools 演示包自己的包名，不是固定 SDK 目录
3. **路径分界**：Android 10（API 29）及以上走 `/sdcard/Android/data/{包名}/files`，Android 9 及以下走 `/sdcard/sdk`（2026-10-27 API 28 实测 log.log 生成于 `/sdcard/sdk`）
4. **机型差异**：部分机型路径可能不同，enable 双路径全部写入、log 探测互为兜底
5. **原版包无 SDK**：`Tools_2022.3.50f1.apk`（C# 原版包）、`Tools_c++.apk`（C++ 原版包）均未集成 SDK，跑不出 log.log 是正常现象；验证 enable/日志逻辑必须用 Sdk/ANO/ACE 系列 SDK 接入包
6. **验证机制**：写入后通过 `cat` 验证内容是否匹配，确保 enable 设置成功
