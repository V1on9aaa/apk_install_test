一、改动背景
apk_install_test 项目存在两个核心缺陷：

无法处理系统安装器弹窗 — 使用 pm install 安装 APK 时，Android 系统可能弹出"仍要安装"、“继续安装”、"完成"等弹窗，导致安装进程被阻塞或失败
无法处理权限申请弹窗 — 应用启动后，可能会弹出"允许"、"始终允许"等权限申请弹窗，导致应用无法正常进入前台
参考项目 apk_install 中通过 AndroidPopup 类 + popup_config.yaml 配置 + OCR 兜底 + adb tap 兜底实现了完善的弹窗处理机制。

二、改动方案
只修改一个文件：core.py

改动分为三部分：

2.1 新增弹窗配置常量
在文件顶部定义四个列表：

配置	作用
INSTALL_POPUP_TEXTS	安装过程中需要点击的弹窗文本（“仍要安装”、"继续安装"等）
PERMISSION_POPUP_TEXTS	权限申请弹窗文本（“允许”、"始终允许"等）
INSTALL_PKG_NAMES	系统安装器包名列表，用于检测安装弹窗是否在前台
PERMISSION_PKG_NAMES	权限弹窗包名列表，用于检测权限弹窗是否在前台
2.2 新增 PopupHandler 类
这是改动的核心，提供完整的弹窗处理能力：

PopupHandler
├── 初始化: 接收 device 序列号，延迟连接 uiautomator2
│
├── 检测层
│   ├── get_ui2_texts()      → 通过 u2.dump_hierarchy() 获取当前界面所有可见文本
│   └── get_foreground_package() → 获取当前前台包名
│
├── 点击层（两层兜底）
│   ├── click_text()          → 第一层：uiautomator2 的 text().click()
│   └── adb_tap()             → 第二层：adb shell input tap 坐标点击
│
├── 辅助层
│   └── keyevent()            → adb shell input keyevent 模拟按键
│
├── 弹窗处理层
│   ├── handle_popup_by_text()    → 遍历文本列表，找到匹配的文本并点击
│   ├── handle_popup_by_package() → 检测前台包名是否在弹窗列表中
│   ├── handle_install_popups()   → 持续处理安装弹窗，直到超时或弹窗消失
│   ├── handle_permission_popups()→ 持续处理权限弹窗，直到超时或弹窗消失
│   └── handle_all_popups()       → 通用处理，同时处理安装和权限弹窗

点击兜底策略：
先用 uiautomator2 的 text().click() 点击
如果失败，通过 adb shell input tap 获取控件坐标后点击
2.3 修改原有函数
函数	改动内容
install_apk()	安装过程中启动独立线程并行处理安装弹窗；安装失败后先处理弹窗再重试
launch_app()	启动后逐个处理权限弹窗和其他弹窗
wait_and_monitor()	每轮检测前先处理弹窗
switch_background_foreground()	切换前后台后处理弹窗
kill_and_relaunch()	杀进程重启后处理弹窗
三、功能逻辑流程
安装流程（install_apk）
开始安装
  │
  ├─ push APK 到 /data/local/tmp/temp.apk
  │
  ├─ 启动弹窗处理线程（daemon=True）
  │     └─ 循环调用 handle_install_popups()
  │           ├─ dump_hierarchy 获取界面文本
  │           ├─ 匹配 INSTALL_POPUP_TEXTS 中的文本
  │           ├─ 找到 → u2.click() 或 adb tap 兜底
  │           └─ 未找到 → 检查前台包名是否还在安装器列表中
  │
  ├─ 执行 pm install -r -d -g -t
  │
  ├─ 停止弹窗处理线程
  │
  ├─ 清理临时文件
  │
  ├─ 安装成功？ → 返回 True
  │
  └─ 安装失败？
       ├─ 处理弹窗（10秒超时）
       └─ 重试安装（同样并行处理弹窗）
启动流程（launch_app）
开始启动
  │
  ├─ monkey -p package -c LAUNCHER 1
  │
  └─ 循环检测（最多5次，每次间隔3秒）
       ├─ 处理权限弹窗（5秒超时）
       ├─ 处理其他弹窗（3秒超时）
       └─ 进程存活？ → 再处理一次弹窗 → 返回 True
  │
  └─ 全部失败？
       ├─ am start 启动
       ├─ 处理权限弹窗（8秒超时）
       ├─ 处理其他弹窗（5秒超时）
       └─ 进程存活？ → 返回 True
运行监控流程（wait_and_monitor）
每5秒循环检测
  │
  ├─ 处理弹窗（3秒超时）
  │
  ├─ check_crash()
  │   ├─ 进程存活？
  │   ├─ 前台包名匹配？
  │   └─ 无 ANR？
  │
  └─ 闪退？
       ├─ 再处理一次弹窗（可能是弹窗导致"不在前台"）
       └─ 再次检测 → 仍闪退 → 返回 False
四、弹窗处理的时间间隔说明
安装阶段（install_apk）
handle_install_popups(timeout=5)
  └─ 循环（最多5秒）：
       ├─ handle_popup_by_text()  → 检测并点击弹窗
       ├─ 点击成功 → sleep(1) → 继续
       ├─ 点击失败 → 检查前台包名是否还在安装器列表中
       │   ├─ 还在 → sleep(0.5) → 继续
       │   └─ 不在 → break
       └─ 超时 → 退出

运行监控阶段（wait_and_monitor）
wait_and_monitor(interval=5)
  └─ 每5秒循环一次：
       ├─ time.sleep(5)                    ← 先等5秒
       ├─ handle_all_popups(timeout=3)     ← 处理弹窗（最多3秒）
       └─ check_crash()                    ← 检测闪退

前后台切换 / 杀进程重启阶段
switch_background_foreground / kill_and_relaunch
  └─ 每次操作后：
       ├─ handle_all_popups(timeout=5)     ← 处理弹窗（最多5秒）
       └─ handle_permission_popups(timeout=5) ← 处理权限弹窗（最多5秒）

五、改动文件清单
文件	改动类型	说明

六、依赖要求
需要安装 uiautomator2：
pip install uiautomator2
七、设计要点
并行处理：安装过程中弹窗处理在独立线程中运行，不阻塞安装主流程
两层兜底：uiautomator2 点击失败时，自动降级到 adb shell input tap 坐标点击
全流程覆盖：安装 → 启动 → 运行监控 → 前后台切换 → 杀进程重启，每个环节都处理弹窗
超时保护：每个弹窗处理都有超时限制，避免无限等待
弹窗文本可扩展：只需在列表中添加文本即可支持新的弹窗类型
